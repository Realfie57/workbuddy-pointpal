# WorkBuddy PointPal（积分桌宠）

一个能贴在桌面上的小挂件：角色举着一块**纯黑屏幕**的平板，屏幕上实时显示你的 **WorkBuddy 积分余额**。
余额每下降一个「扣费步长」（默认 **1 积分**），角色就红闪一下 + 轻微震动，同时**播放一次打击音效**，
头顶弹出红色的 **-1** 向上飘并渐隐（数字和屏幕文字会**跟着角色一起抖**）。

> 原名「WorkBuddy积分桌宠」，2026-09-29 起更名 **WorkBuddy PointPal**。
> exe 版的数据目录同步改为 `%LOCALAPPDATA%\WorkBuddy PointPal`，首次运行会自动从旧目录
> （`%LOCALAPPDATA%\WorkBuddy积分桌宠`）把 `token.txt` 和 `state.ini` 复制过来，不用重新粘贴凭证。

本项目基于开源项目 [DSH 余额桌宠](https://github.com/VKmich16/VK-1)（Windows 原版，DSH/DeepSeek 余额）
改编：**美术形象、动画、音效、账本架构完全沿用原作**，数据源替换为 WorkBuddy 积分接口。

## 一、启动

三种形态，任选其一：

* **Setup 安装包（推荐分发）**：双击 `WorkBuddy PointPal Setup.exe`，向导里选安装文件夹、
  桌面/开始菜单快捷方式、是否开机自启。仅装到当前用户，**无需管理员权限**。详见「五、分享给别人」。
* **便携 exe**：双击 `WorkBuddy PointPal.exe` 即可，免安装、无 PowerShell 窗口
  （Win10/11 自带 .NET Framework 4.x）。
* **ps1 脚本版（开发用）**：双击 **`启动 WorkBuddy PointPal.vbs`**。

启动后：

1. 角色出现在**屏幕左下角**（默认 **8cm 高**，宽度随角色画幅自动适配），平板上几秒后显示积分。
2. 开机自启：安装时勾选即可（本质是把快捷方式放进 `shell:startup` 启动文件夹）；
   手动设置也一样：`Win + R` 输入 `shell:startup`，把 exe（或 vbs）的快捷方式丢进去。

前提（仅 ps1 版）：**Windows PowerShell 5.1**（系统自带）；**Node.js** 可选（仅当 .NET 网络通道被系统策略拦用时兜底）。

### 关于登录凭证（重要，与原版最大的不同）

原版读的是 DeepSeek 公开 API Key；**WorkBuddy 没有公开 API Key 机制**。
本作启动时按以下顺序找凭证：

1. 环境变量 `WBPET_TOKEN`（+ 可选 `WBPET_UID`）；
2. 同目录 `token.txt`（第 1 行 token，可选第 2 行 uid）；
3. 自动探测本机常见位置（`~/.workbuddy/token.txt` 等）；
4. 都找不到 → 弹出输入框让你**手动粘贴**。

> **为什么没有做成"自动读取 WorkBuddy 客户端的登录态"？**
> 开发时做过完整调研：WorkBuddy 桌面端的登录凭证由 Electron safeStorage / keyblob 主密钥体系
> 加密存放（AES-256-GCM，密钥由独立的 protector key 包裹），磁盘上没有可复用的明文，
> Cookie 库为空，localStorage 里也没有 token。要自动读取就得完整重实现它的内部解密链——
> 既脆弱（版本号 `static-v1` 明示会轮换），又等于绕过它刻意设计的凭据保护。
> 所以正式方案是**手动粘贴一次 Token**，和原版 `apikey.txt` 的思路一致。

**手动获取凭证的步骤（推荐：整段 cURL）**（凭证输入框**左下角的「如何获取凭证...」按钮**里也有同一份说明）：

1. 浏览器打开 [www.workbuddy.cn](https://www.workbuddy.cn) 并登录；
2. 按 `F12` → **Network（网络）**；
3. 选择查看 **Doc（文档）** 类型的请求，**刷新页面**；
4. 找到 `www.workbuddy.cn`，**右键** →「复制」→「**以 cURL 格式复制**」（bash）；
5. 右键桌宠 →「设置登录凭证」，**整段粘贴**。程序自动提取 Cookie + User-Agent。

> **凭证会过期**：登录凭证本质是浏览器会话，**过一段时间会失效**。
> 失效后网关返回 401，桌宠屏幕上会**亮起一个红点**提醒你——
> 此时照上面步骤重新复制一次，在**托盘图标上右键**重新设置即可。
> 凭证输入框**最下面那行**也写了一句同样的提醒（就这一句），忘了可以直接照着看。

> **为什么必须带 User-Agent？** 实测（2026-09-29，多组对照实验）：
> 网关把登录会话**绑定到浏览器 User-Agent**——同一 Cookie，UA 差一个版本号都 401；
> 只粘 Cookie 不粘 UA 也 401。整段 cURL 两者都含，是最稳的方式。
> 也兼容：Bearer Token（桌面端方式）、裸 Cookie（需已存有对应 UA）、`uid:凭证`。
> **注意**：Edge 大版本升级后 UA 会变，凭证随之失效，重新复制一次即可。

* **后台自动轮询**（默认每 5 秒）：余额下降时**一步长一步长地扣**，每次扣费都完整播一遍动画 + 音效。

  想看连续动画就用「演示连续扣费」。

## 三点五、扣费的节奏

**步长默认 1 积分，右键可调（0.1 / 1 / 5 / 10 / 自定义）。**

* 每次扣费之间**间隔 0.2 秒**，每次都完整播放红闪 + 震动 + 音效 + 飘字。
  间隔短了之后，飘出的数字会**像连击那样向上错开排成一条串**，不会叠在一起看不清。
* **规则**：云端余额一有变化，就把差额换算成 **N 个步长**，然后一个一个地扣。

> 例：余额从 3000 变成 2995（少了 5，步长 1）
> → 连续扣 5 次：`-1`、`-1`、`-1`、`-1`、`-1`，
> 屏幕数字 3000 → 2999 → … → **2995**，
> 每一次都有完整的红闪 + 震动 + 音效 + 飘字，五个 `-1` 依次向上串成一条。

**数字绝不会在没动画的情况下变化**：数字只在扣费那一帧变化，而且一次只变一个步长。

**"实时"指的是延迟小**：服务器那边余额一变，下一次轮询（默认 5 秒）就把它换算成扣费次数，
**第一次扣费当帧就会弹出**，不会压着等下一轮。

> 大额跳变的保护：一次最多排队 40 次（默认步长下 40 积分），避免云端一次性跳很多时动画播上好几分钟。
> 剩下的部分会在后续轮询里继续补完。

## 四、它是怎么工作的

* **积分来源**：`POST https://www.workbuddy.cn/billing/meter/get-user-resource-summary`
  （body 为 `{}`；鉴权二选一，程序自动识别：`Authorization: Bearer <token>`（桌面端方式）
  或 `Cookie: <整段cookie>`（网页版方式）；**Cookie 方式必须同时带上当时浏览器的
  `User-Agent`**——网关把会话绑定在 UA 上，差一个版本号都 401；另加可选 `X-User-Id`
  与 `Accept-Language: zh`）。
  余额 = 响应 `data.Packages[].CycleRemainCapacity` 求和（托盘提示还会显示
  `CycleTotalCapacity` 求和作为总量）。
  解析用大小写不敏感的正则扫描而非固定 JSON 路径，接口外层（`code/msg/data` 信封）变动也能扛。
  （.NET 通道的 `HttpClientHandler` 必须显式 `UseCookies = false`，
  否则默认 CookieContainer 会静默丢弃手动设置的 Cookie 头——2026-09-29 实测踩坑。）
* **两个数值**：
  * `真实余额`：接口刚读到的值；
  * `屏显余额`：平板上打印的数字，**只在扣费那一帧变化，且一次只变一个步长**。
  账面基准与屏显余额成对维护，欠款 = 账面基准 − 真实余额，
  每次读数都**重新推导**，所以任何时刻到达的数据都不会让数字失同步。
* **逐步长结算**：欠款换算成 N 次扣费，一次一个、间隔 0.2 秒，每次都完整播动画 + 音效。
* **轮询与延迟**：默认每 5 秒问一次。取数在**后台线程**做（避免卡住界面），拿到结果后**当帧结算**。
* **"立即刷新积分"= 立即对齐**：屏显直接等于真实余额（不足一步长的零头也抹平），并清掉演示偏移。
* **"测试一次扣费"是纯显示**：只把**打印出来的数字**往下挪（一个显示偏移），不碰真实余额、也不碰步长基准。
  所以按几次之后再「立即刷新积分」，数字会干净地回到真实值。
* **凭证过期**：接口返回 401 时屏幕角落亮红点、状态变为「凭证已过期」，日志有明确提示，重新粘贴即可。
* **红闪**：角色贴图预处理为一张纯红剪影（保留 alpha）。**叠加强度随尺寸自适应**
  （小尺寸约 64%，大尺寸约 30%），避免 8cm 时糊成一团红。
* **震动**：阻尼正弦抖动（约 ±8px 峰值，0.55 秒衰减），**固定像素幅度**而不是按比例缩放。
  同时生效的受伤层最多 3 个，并且总位移有硬上限，避免连点时把角色甩出屏幕。
  抖动偏移同时施加到屏幕文字和飘字上，三者严格同步。
* **音效**：走 Win32 **MCI** 接口，预先开 4 个别名槽位。每次飘字弹出就找一个空闲槽位播放，
  **互不打断、可以叠着响**。为避免目录名里的中文被编码破坏，程序先切到音效所在目录再用文件名打开。
* **屏幕**：黑色内屏保持原样不涂任何颜色，只画「标签」和数字（浅色字 + 深色描边），
  用三点映射贴合到屏幕四边形上。标签/数字过长时**自动缩小字号**适配。
* **尺寸**：按真实显示器 DPI 换算厘米；若进程拿不到 DPI 感知，会退回读显示器实际 DPI。
* **窗口**：WinForms 无边框 + 分层窗口（逐像素 alpha），`WM_NCHITTEST` 对透明像素返回 `HTTRANSPARENT` 实现穿透点击。

## 五、分享给别人

### 方式一：Setup 安装包（推荐）

把 `WorkBuddy PointPal Setup.exe`（约 14 MB）发给对方，双击后是一个标准的安装向导：

1. **欢迎页** → 2. **选择安装文件夹**（默认 `%LOCALAPPDATA%\Programs\WorkBuddy PointPal`，可浏览更改；
   页面实时显示「将安装到：<目录>，预计需要 <实际大小> 空间」）
   → 3. **附加任务**：桌面快捷方式（默认开）、开始菜单快捷方式（默认开，含卸载入口）、
   开机自动运行（默认关），**分隔线之下**另有一项
   「在桌面创建「WorkBuddy & PointPal」快捷方式」（默认关）→ 4. 安装 → 5. 完成（可勾选立即运行）。

#### 同一台电脑只允许装一份（安装前自动检查）

安装程序**一启动**就会检查本机是否已经装过 `WorkBuddy PointPal`（查注册表卸载项
`HKCU` 与 `HKLM` 两处）。如果已经装过，会先弹窗提醒：

> 检测到这台电脑上已经安装了 WorkBuddy PointPal。
> 安装位置：<原安装目录>
> 同一台电脑不需要安装多个 WorkBuddy PointPal。
> 点击「确定」将先卸载原有软件，卸载完成后自动继续安装；
> 点击「取消」将终止本次安装。

* 点**确定** → 自动运行**原有软件的卸载程序**（会走它自己的「确定要卸载吗」和
  「要同时删除数据吗」两个询问，`Uninstall.exe` 的 UI 会正常出现），
  **等它彻底结束后**才继续本次安装，避免两份程序抢同一套快捷方式、自启项和登录凭证。
* 点**取消** → 本次安装直接终止（退出码 2），你的机器不会有任何改动。
* 原有软件**卸载失败或中途取消** → 安装也会终止并给出提示（退出码 3），
  不会硬装成两份，此时先手动卸干净再重来。
* 注册表里记的位置**找不到 `Uninstall.exe`**（比如文件夹被手动搬走了）→ 会明确告诉你
  去「应用和功能」卸载或手动删文件夹，而不是默默装第二份。
* **便携版不受影响**：便携 exe 不写注册表，所以**不会被检测到**，想放几份都行
  （这也意味着便携版和安装版可以共存）。


#### 「WorkBuddy & PointPal」双启动器

一次双击同时启动 **WorkBuddy + 桌宠**，省掉分别点两次。

* **安装目录里永远留一份备用**：无论上面那个勾选项是否勾选，
  安装目录下都会出现 `WorkBuddy & PointPal.vbs`。它不依赖桌面快捷方式，
  直接双击也能用——放在桌宠 exe 旁边时，它靠**注册表卸载项**（`InstallLocation`）
  自动找到桌宠，不写死任何盘符。
* **勾选后额外在桌面**生成 `WorkBuddy & PointPal.lnk`。这个快捷方式指向安装目录里那份备用副本，
  并把安装目录作为参数传给它（`%1`），所以**快捷方式与备用副本永远指向同一个桌宠**，
  不会各自找到不同版本。
* **两边都能自动定位，装到哪都不怕**：桌宠先查注册表，再依次尝试
  `%LOCALAPPDATA%\Programs`、`%ProgramFiles%`、`%ProgramFiles(x86)%`、`%ProgramData%` 下的
  `WorkBuddy PointPal\`；WorkBuddy 没有卸载登记项，改用一份候选路径清单（同样覆盖
  `%LOCALAPPDATA%\Programs\WorkBuddy\`、两个 `Program Files` 等），最后一个回退才是
  硬编码的 `D:\` / `C:\Program Files\WorkBuddy`。**找不到的那一方会被安静跳过**，不会报错。
* **桌宠已在运行就不重复启动**（WMI 查进程），所以常驻托盘时点这个快捷方式只会把 WorkBuddy 拉起来。
* **快捷方式的「目标」是 `wscript.exe`，不是那个 vbs 本身**：Windows 只允许把**目标是
  可执行文件（.exe）**的快捷方式固定到任务栏；如果目标直接指向脚本（`.vbs`/`.bat`/`.ps1`）
  或另一个 `.lnk`，任务栏会**拒绝固定**（拖拽显示禁止图标，右键菜单里也没有「固定到任务栏」）。
  所以 vbs 的路径是通过**参数**传给 `wscript.exe` 的，效果完全一样，但能正常固定。
* **专属图标**：安装目录里同时会放一份 `WorkBuddy & PointPal.ico`（WorkBuddy 风格的绿色卡片图标），
  桌面快捷方式的图标就取自它。VBS 自身无法携带图标，所以必须由快捷方式显式指定，
  否则会显示成 WSH 脚本的默认图标。
* 该文件是 **UTF-16LE + BOM** 编码的 VBS，WSH 原生按 Unicode 读，名字里的 `&` 和中文路径都不会乱码。
* 想排查它到底找到了什么：设环境变量 `WBPET_BUNDLE_TRACE=1` 再双击，
  会写出 `%TEMP%\wb-bundle-launcher.log`（记录桌宠路径、WorkBuddy 路径、桌宠是否已在运行）。
  不设这个变量时它**完全静默**，不留任何文件。

* **安装范围自动推断，无需选择**：装到普通文件夹 = 仅当前用户（不写 HKLM，全程无 UAC）；
  装到 `C:\Program Files` 等需要管理员权限的目录 = 自动按全机安装处理（写 HKLM、公共桌面/开始菜单），
  且只在点「安装」那一刻才弹 **UAC**（目录页会提前显示一行提示）。
  同意 UAC 后由独立的提权进程完成安装并弹出结果（原向导直接关闭；提权进程**不会**替你启动桌宠，
  避免桌宠带管理员权限运行）；取消 UAC 则什么都不装。
* **自动补产品子文件夹**：若所选目录名不是 `WorkBuddy PointPal`，会自动在其下创建该子文件夹
  （例如选 `D:\Tools` → 实际装到 `D:\Tools\WorkBuddy PointPal`）。
* **开机自启的实现**：在 `shell:startup` 启动文件夹放一个快捷方式。
  （最初用的是 HKCU Run 注册表项，但实测发现电脑管家类软件会在 1 秒内把新加的 Run 值删掉，
  启动文件夹快捷方式则被放行——2026-09-29 实测，故改用它。）
* **卸载**：开始菜单「WorkBuddy PointPal → 卸载」，或系统「设置 → 应用」里找 WorkBuddy PointPal。
  **一次卸载会移除本机上的全部安装**（当前用户的 + 所有用户的，若都存在会一并清除，
  并在确认框里说明），无需任何选择；存在全机安装时会请求一次 UAC（取消则什么都不动）。
  卸载会删除程序文件、全部快捷方式、自启项和注册表卸载项；
  **数据目录默认保留**（卸载时会单独询问是否一并删除）。
* **数据目录**：`%LOCALAPPDATA%\WorkBuddy PointPal\`——美术资源首次运行自解压（只补缺失文件），
  `token.txt`、`state.ini`、`pet.log` 也都在那里。
* **凭证**：对方第一次启动会弹出**和右键「设置登录凭证」完全相同**的输入框——
  多行编辑框、底部粘贴提示、左下角「如何获取凭证...」按钮齐备，不再是孤零零一个单行输入框
  （取消也能用，先离线显示 `--`）。
* **静默安装**（方便批量/脚本）：`"WorkBuddy PointPal Setup.exe" /S /D=目录 /DESKTOP=1 /STARTMENU=1 /AUTORUN=0 /BUNDLE=0`
  （`/BUNDLE=1` 额外创建「WorkBuddy & PointPal」桌面快捷方式，默认 0）；
  目录为系统位置时自动按全机安装（进程本身必须已是管理员，否则直接报错拒绝、不弹 UAC；
  也可用 `/MACHINE` 显式指定全机安装）。
  静默卸载：程序目录下 `Uninstall.exe /S`（加 `/DELETEDATA=1` 连数据一起删；
  检测到全机安装时同样需要管理员身份）。
* **重新编译**（改了 `wb_pet.cs` 之后）：先 `build_exe.ps1` 再 `build_setup.ps1`。
* exe 未签名，SmartScreen 首次可能提示，点「更多信息 → 仍要运行」即可。

### 方式二：便携 exe

`WorkBuddy PointPal.exe`（约 13 MB）是**自包含单文件**：全部美术（8 个角色造型）、音效、图标都嵌在 exe 里，
任何 Win10/11 机器**拷过去双击即用**——系统自带 .NET Framework 4.x，无需安装、无需管理员权限、无 PowerShell 窗口。
数据目录与安装版共用 `%LOCALAPPDATA%\WorkBuddy PointPal\`；
支持自检参数 `--selftest` / `--shot` / `--simchain`（在 cmd 里运行可见输出）。

### 方式三：整个文件夹（ps1 脚本版）

**要发整个文件夹，不能只发启动程序。** 启动器只是个外壳，真正干活的是同目录下的
`wb_pet.ps1` + `wb_pet.cs` + `sprite.png` + `characters\` + `hit.mp3`；少一个都跑不起来。

打包前请删掉这几样（它们只属于你本人）：

| 文件 | 为什么不能发 |
| --- | --- |
| `token.txt` | **里面是你的登录 Token** |
| `pet.log` / `error.log` | 运行日志，含你的积分数值与路径 |
| `state.ini` | 你调过的尺寸、步长与标签，对方不需要继承 |

脚本里**没有写死任何绝对路径或用户名**（用的是脚本自身所在目录、`%USERPROFILE%`），
所以对方解压到任何目录都能直接用。

对方第一次启动时会**弹出凭证输入框让他填自己的 Token**（和右键「设置登录凭证」是同一个
多行界面，带「如何获取凭证...」按钮；取消也能用，只是先离线显示 `--`）。

## 七、自检与排错

```powershell
# 渲染一帧到 selftest.png，并打印尺寸/账本状态
powershell -ExecutionPolicy Bypass -File .\wb_pet.ps1 --selftest

# 真实开窗跑 2.5 秒：打印抖动偏移、文字落点，并验证刷新语义
powershell -ExecutionPolicy Bypass -File .\wb_pet.ps1 --shot

# 喂一串模拟余额，检查"按步长扣费 + 拆步长补扣 + 演示不冻结"（离线、不需要凭证）
powershell -ExecutionPolicy Bypass -File .\wb_pet.ps1 --simchain
```

exe 版同样支持这些参数（在 cmd 里运行可见输出），数据读写都在 `%LOCALAPPDATA%\WorkBuddy PointPal\`：

```cmd
"WorkBuddy PointPal.exe" --shot
```

其余自检参数（全部**只读**，不会写你的 `token.txt`，也不会抢单实例锁）：

| 参数 | 作用 |
| --- | --- |
| `--credtest` | 凭证解析器回归（11 项）。会喂合成夹具，但内置断言保证 `token.txt` 字节不变 |
| `--credcheck <文件>` | 端到端：拿一个真实 cURL 文件过一遍解析 + 真发一次请求，报 HTTP 状态 |
| `--soundtest` | 音效槽位状态判定表（18 项，纯逻辑，不需要声卡） |
| `--soundprobe` | 真实设备探针：开池、按 0.2s 节奏打一串，逐条打印 MCI 状态 |
| `--soundsoak [n]` | 长时间节奏浸泡，默认 50 次，看有没有丢音 |
| `--soundab [n]` | A/B/C 对照：三种历史判定规则各跑一轮，附一次状态转换计时 |
| `--abouttest` | 「关于…」自检：证明它确实是**倒数第二项**（退出之上）、版本号与 exe 一致 |
| `--aboutsheet <png>` | 把「关于」文案渲染成图片，便于校对措辞 |
| `--toksheet <png>` | 把**凭证输入框**渲染成图片，并打印布局自检（提示文字是否装得下、编辑框是否让开）。配 `WBPET_UI_SCALE=1.5` 可模拟缩放，验证高 DPI 下不截断 |

安装包（`WorkBuddy PointPal Setup.exe`）另有一个只读自检参数：

```cmd
"WorkBuddy PointPal Setup.exe" /CHECKONLY
```

它**只查不改**，把「是否已装过」的判定结果打印出来就退出
（`installed=True/False`、`location=…`、`uninstallerPresent=…`，退出码 0=已安装 / 1=未安装）。
装了没装、注册表指到哪、那里有没有卸载程序，一眼可查——用来排查
「为什么安装程序说我已装过」这类问题。


`--simchain` 会输出类似：

```
  read 2999 -> printed 3000 -> after cues 2999
  read 2998 -> printed 2999 -> after cues 2998

a 5-credit drop becomes FIVE animations:
  server -> 2995  : owed 5  -> printed still 3000
    +0.3s -> printed 2998 ...
  settled -> printed 2995  (3000 - 5 = 2995, 5 animations)
```

**角色不出现 / 一闪而过**
用 `启动（调试窗口）.cmd`，再看 `error.log` 与 `pet.log`。

**没有声音**
看 `pet.log`：正常会有 `sound ready: ... volume=80`。
* `sound pool failed` → 音效文件缺失或被占用。
* `sound: nothing played` → 系统 MCI 打不开该 mp3，换一个试试。
* 静音：设 `WBPET_SOUND=0`，或删掉 `hit.mp3`。

**屏幕一直显示 `--`**
看 `pet.log`：`no token` → 右键「设置登录凭证」；
`HTTP 401` → 凭证过期/不对，重新粘贴（可能需要 `uid:Token` 形式）；
`cannot parse response` → 接口结构变了。屏幕角落出现**红点** = 当前离线。

**红闪太强/太弱**
`wb_pet.cs` 里 `double maxTint = Math.Max(0.30, 0.64 - _scale * 0.75);` 改这两个数即可。

## 八、改脚本前必读

`wb_pet.ps1`、`wb_pet.cs`、`build_exe.ps1` 是**故意写成纯 ASCII 的**（界面上的中文用 C# `\uXXXX` 转义）。
因为 Windows PowerShell 5.1 在没有 BOM 时按 ANSI 读取脚本，直接写中文会乱码甚至解析失败。
要改脚本请**只写英文**，中文用 `\uXXXX` 转义；改 `说明文档.md` 这类文件请用支持 UTF-8 的编辑器。

**所有逻辑都在 `wb_pet.cs` 里**（ps1 与 exe 共用同一份源码，改一处两边同时生效）：
`wb_pet.ps1` 只是「读凭证 + Add-Type 加载 wb_pet.cs」的壳；exe 则由 `build_exe.ps1` 从同一份
`wb_pet.cs` 编译（入口是文件末尾的 `ExeEntry.Main`）。改完记得跑一次 `build_exe.ps1` 让 exe 同步。

## 九、想微调节奏

步长默认 1、间隔固定 0.2 秒（间隔刻意不可调，理由同原版）。
真要改，只能改源码常量（在 `wb_pet.cs` 中部，**只写英文**）：

| 常量 | 默认 | 含义 |
| --- | --- | --- |
| `_step`（右键可调） | `1` | 每次扣多少积分 |
| `CueGapSec = 0.2` | 0.2 | 两次扣费之间的间隔 |
| `MaxCuesPerPoll = 40` | 40 | 单次轮询最多排队多少次，防云端大跳变时动画播太久 |

轮询快慢用环境变量 `WBPET_POLL_MS`（默认 5000 毫秒，最小 1000）。
